## Summary (5 lines)
1. Size is not the problem in this scope: no module is over 600 lines (largest `workflow/run.py` 417, `workflow/settings.py` 273) and no function is over 80 lines (largest `rolling_run.run_rolling` 56, `colab_ops._run` 56). The structural debt is duplicated orchestration and duplicated constants, not big units.
2. The most serious findings are correctness and identity gaps: whole-timestamp models are predicted in 512-row slices that cut timestamps (C-01); `RunIdentity` hashes fit, model, trainer config and optimizer, but not the split, `input_timeframes`, `selection_metric` or `StageSettings` (C-03, C-04, C-05); the rolling summary reads `fold_row.json` files of any earlier configuration in the same `out` (C-06).
3. Four of six job entries (`staged`, `rolling`, `gates`, `device_smoke`) ignore `--max-minutes`, so the runner can only SIGKILL them at `max_minutes*60 + 120 s` (C-07). `docs/COLAB_OPS.md:65` documents only `rolling`.
4. Settings: several field combinations are unguarded or silently dormant (C-08, C-11), defaults are spread over five places (C-16, C-17, C-33), and the "which fields are per-run vs configuration" list exists five times and already disagrees (C-15).
5. Clarity: 7 modules in scope have no card, "best-epoch weights" is printed where `restore_best_weights` / EMA / `last` may apply, and `run.py:6` says the panel run is parked while `jobs/panel.py` is live. Dead code: `rolling.run_rolling_study`, `staleness.py`, `colab_ops/scripts/run_models.py`.

Number of findings: 35.
