# Hardening audit D: `src/nig_timenet_torch/data/` and `data_io/` (read-only, structure + clarity)

## Summary
1. Size is healthy: no module > 600 lines (largest `data_io/synthetic.py` 282, `data/build.py` 279, `data/settings.py` 285) and no function > 80 lines (largest `add_market_residual` 73, `build_logret_dataset` 72, `add_indicator_channels` 62); the real debt is DUPLICATION, not size.
2. The `data` / `data_io` split is not what its names or docstrings say: `data_io` holds readers, a writer-dependent set of 5 derived-artifact tools, 3 test-environment generators, a downloader and a codec registry, and it depends on `data` (lazy imports) while `data` depends on `data_io` (cycle hidden from the G7 ratchet).
3. The 5 derived-artifact tools (lower_timeframe, indicator_channels, btc_relative, market_channel, market_residual) copy the same ~60-line skeleton (load, checks, cache/fetch, ThreadPool, write_artifact, derivation json, argparse) and three of them re-implement RSI / stochastic / relative volume; one is imported from another's private `_coin_candles`.
4. Contract vs code: the doc says `files` hashes "every file except manifest.json" but derivation_*.json files are written after the hash and are never hashed; also three different definitions of "label time" and a "no `center=True`" pitfall that the fractal feature breaks (it is causal only through a matching shift).
5. Leakage (D2) holds in everything read, but it is not obvious in 6 places (D-15, D-17, D-24, D-25, D-26, D-27); none was shown to leak.
