# Hardening audit 2026-11 (step H0, auditor)

Scope: clarity, flexibility and modularity of `src/nig_timenet_torch/` (61 modules, 5,883 lines) and `tests/`
(80 files, 5,785 lines) at `main` = `7c453af`, compared with the TF project `yuosef772424/crypto-signal-prediction`
(read only). The plan that fixes these findings is `docs/hardening/PLAN.md`; the review of the CSV registers is
`docs/reviews.md`.

Method (independence rule of the TF audit protocol): docstrings, comments and docs were treated as claims. For each
area the clean state was written down first, then the code was checked against it. Every row below has evidence a
reader can re-run: a `path:line`, a command and its output, or a counted list. Baseline at the start: `ruff check src
tests` -> "All checks passed!"; `pytest -q` -> "515 passed in 31.84s".

Re-runnable commands used (from the repo root, with the CPU venv active):

```
# ratchet sites (G1/G2/G4/G7/G8/C2) and the longest functions
cd tests && python -c "import scan; print(scan.output_name_literals()); print(scan.mode_name_comparisons())"
# every string ==/!= comparison in src (47 today; 17 in model/builder.py)
python - <<'EOF'
import ast, pathlib
for p in sorted(pathlib.Path("src/nig_timenet_torch").rglob("*.py")):
    for n in ast.walk(ast.parse(p.read_text())):
        if isinstance(n, ast.Compare) and any(isinstance(o, (ast.Eq, ast.NotEq)) for o in n.ops):
            if any(isinstance(c, ast.Constant) and isinstance(c.value, str) for c in [n.left, *n.comparators]):
                print(p, n.lineno)
EOF
# hard-coded price-target tuples (11 sites)
grep -rn '"high", "low", "close"\|{"high", "low", "close"}\|("high", "low")' src
```

Severity scale: **blocks model work** (a model step cannot proceed safely, or produces silently wrong numbers),
**slows development** (more files to edit, a round trip, a silent misconfiguration risk), **cosmetic**.

## For H0c: model / trainer weaknesses and missing post-training checks

Not planned here (H0c writes the post-hardening ROADMAP). Each line names where it was seen.

- No gradient clipping, no weight-decay exclusions, no EMA weights (`trainer/trainer.py:178-186`; B-018). The TF
  baseline trained with `clip_norm=1.0`.
- Confidence target is the batch-normalised |error| with a diversity penalty `std >= 0.15` (`trainer/tasks.py:77-87`;
  B-005) and NIG floors (`model/nig_layers.py`; B-001): the T6 switches 3 and 4.
- Weight init is the torch default (B-007); TF used glorot / orthogonal.
- Input pipeline: every batch is a fancy-index gather from CPU tensors and a synchronous `.to(dev)`
  (`trainer/trainer.py:223-224`), no pinned memory or prefetch: a small model (d_model 64) may leave the GPU idle; step
  time is still unmeasured (B-008) and the measure itself is biased (HF-37).
- `linear_path` = Linear(T x F (x2 with level passthrough) -> d_model) is added to the encoder readout
  (`model/builder.py:215-216,255-256`) and level passthrough re-injects the raw level into the tokens
  (`:170-179`): check whether the model is dominated by this linear map (passthrough dominance: share of the readout
  output variance and of the gradient coming from `linear_path` vs the encoder).
- Missing post-training checks (the health report has target_report, nig_floor, probe and the trainer trace only):
  dead units (share of GELU/ReLU units never active on val), class-head saturation (share of p < 0.01 or > 0.99; the
  BCE clips at 1e-7, `trainer/tasks.py:22`), NIG uncertainty hitting `unc_max=20` (`model/nig_layers.py`
  NIGUncertainty), GRU hidden-state saturation (|h| near 1), attention entropy / collapse (transformer encoder only;
  the default is GRU), prediction collapse (std of prediction / std of label per head), Kendall log-variance drift per
  epoch, train/val gap per epoch, per-coin coverage spread beyond min/max.
- Leakage canaries: a shuffled-label run must give ~0 skill; a future-feature canary; today purity is unit-tested in
  `data_io/split_plan.py` only. B-020 (is `last_candles` timestamp the bar OPEN time?) is still unproven on the real
  artifact.
- The trace measures gradient shares on ONE fixed batch, the first `batch_size` training rows
  (`trainer/trainer.py:300-301`): train rows keep dataset order (`np.flatnonzero`, `data_io/split_plan.py:78`) and the dataset is coin-major (`asset_bounds`), so that batch is one coin's earliest windows.
- Selection metric default is `val_raw_loss` (B-003): T6 switch 2.
